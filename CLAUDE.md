# CLAUDE.md — Fleet View

Factorio 2.1 mod (author holyskib, MIT): draws a player's other space platforms in the
background of the platform they stand on. Release 1 = fleet view; shadow is release 2.

## Layout
- `fleet-view/` — the mod itself (info.json, settings.lua, locale/, changelog.txt; later control.lua, scripts/, prototypes/)
- `tests/` — pure-Lua unit tests: `tests/run.lua` + `tests/test_*.lua` (each returns `{ name = function() end }`, uses `assert`, `assert_eq`, `assert_near`)
- `fleet-view/control.lua` events + remote interface `fleet-view`, registered ONLY when `script.active_mods` has fleet-view-test/-bench/-shot (show/clear/set_setting/transfer_run/configuration_changed/simulate_old_storage/platforms_changed/flush/set_rebuild_ticks/set_min_step/set_no_idle/reset_gather_stats/stats, used by the headless checks; set_setting writes the real mod setting so the real event runs); `scripts/transfer.lua` (zoom transfer, below), `scripts/snapshot.lua` (pure `build_model`/`split_rects` + live `gather`), `scripts/draw.lua` (per-viewer anchors + sprites, ALL on render layer 1 `background-transitions` since 0.4.10 (only layers 0-2 are under the deck, 3+ incl. `decals` draw over bare deck floor (deck mode); NOT `zero`: Visible Planets in Space's planet hides layer-0 sprites above its centre (0.4.3); layers 0-2 sort by sprite target y, not creation order, and the viewer deck's hanging underside joins layer 1's sort at its first empty row); order inside layer 1 comes from SORT-KEY SHIFTS (`scripts/sortkey.lua`, docs/layer-order.md): every fv-* sprite has a downward prototype shift written in data-final-fixes and `plan_ship`'s `add` moves the target up by `sortkey.fold` (shift x runtime scale, turned by `orientation`), so pictures are unchanged and keys sit above them: TOP 50 model tiles (entities, belts, lights, px rects via `fv-px-<h>` per rect height), FLOOR 66 (floor; edge art FLOOR + HANG = keyed at its tile row) -> the whole ship sorts under the viewer's hanging edges and the floor under the buildings; floor/edge/dot sprites carry their size in the prototype `scale` and are drawn at S (shift x runtime scale, and a shift > ~256 tiles is not drawn: `MAX_SHIFT` 85 asserted at load); rotated sprites (ROTATED_TYPES belts/undergrounds/splitters/pipes/walls + their `-sh`, `fv-arm-*`) get turned copies `<name>-fvq<1..3>` with pre-turned shift (`turned_of` in draw.lua); every shifted sprite gets `graphics/pad.png` (256 px, alpha 1/255 corner pixels so the loader cannot trim it, scale 1/64) as FIRST layer: culling ignores the shift and only looks at the first layer's trimmed pixel size, small shifted sprites vanished near the top of the view when zoomed in; entity icons (fallback) are not shifted), belts/undergrounds/splitters/pipes/pipe-to-ground/walls drawn as real sprites with `orientation` (model `ent.rot`), only loader/linked-belt/gate stay dim rects, world-fixed placement (anchor created once at draw time, never teleported for viewer movement; `geom.SCALE` 0.16; `geom.spot` rolls a random spot: angle uniform around the deck bounding-box centre, scaled ship box with a 3-12 tile gap from the deck's tile box, then (0.4.9, `blocked` predicate arg, live = foundation-tile count in `deck_blocked` in draw.lua, NOT "not empty-space": ungenerated corners are `out-of-map`) walked INWARD along its ray (8-tile steps, then 1) while the box grown by the gap touches no deck tile, stopping at the first blocked position (a ring's hole is never used; a rectangle = the bbox spot exactly; ~1 ms per call on a 2000-wide cross), >= `geom.SHIP_GAP` 4 from other ships (24 rolls, then pushed outward), plus a per-ship scale factor 0.85-1.15 on `geom.SCALE` (`box.k`, passed to `plan_ship`); `storage.rng` = LuaRandomGenerator (created lazily from nauvis map seed + tick, never in on_load, survives `reset`; `set_seed` remote for shots); `storage.layouts[viewer platform index]` = {deck = {x, y} centre, ships[idx] = box {x, y, hw, hh, k, ax, ay}} rolled ONCE per ship and shared by all viewers on that platform, dropped by `prune_layout` when the ship has left (show/reconcile/end of leave animation) so a new arrival re-rolls; sizes from `snapshot.gather_bounds` tile scans cached in `storage.bounds`, dropped on tile events; no `set_layout` remote), arrive/leave animation: `reconcile` on platform state change, per-ship steps from `storage.animating`, `anim = {n (0..180, float), dir, side, mover}`; pace: each tick n += the mover platform's live `speed` (km/tick) * 180 / `PLANET_KM` (sqrt(150 / `PLANET_A`), `PLANET_A` = 2.875e-5 tiles/km^2 = the planet backdrop's measured curve: offset depends on distance flown, not time, filmed 2026-10-25), departures clamped to `MIN_STEP` 0.375..`MAX_STEP` 0.6 (5-8 s) (0.4.11, portal versuffer: the planet backdrop slides by the FRACTION of the route, not km: filmed 2026-11-16, shot modes `planet` (1000 km test route `nauvis-fvt-moon` in the shot mod vs nauvis-vulcanus, departures + arrivals, same edge at the same fraction within ~5%) and `moon`/`moonlong`/`moonarrive`/`moonarrivelong` (before/after clips). `geom.planet_km(PLANET_KM, length)` = PLANET_KM * length / 15000 for routes < 15000 km, else PLANET_KM; `planet_km_on(platform)` in draw.lua. Used for the approach window + n, and in `step_of(..., own)`: when the mover is the VIEWER's platform the step is never below the planet's pace on a short route (owner: the clamp exists because ships are nearer than the planet, slower than it reads wrong). Routes >= 15000 km unchanged: moonlong frames byte-identical to 0.4.10), arrivals ignore speed: `ARRIVE_STEP` 0.3 = 10 s (a platform arrives at full speed, 5 s felt too fast); APPROACH (the viewer's own arrival, owner: "follow the factorio way", no clamp): `storage.transit[player]` while its platform is on a space connection, on_tick checks `destination` (schedule's current station, when it is an end of `space_connection`) and `km_to` (distance runs 0..1 from the connection's `from` end in both directions: (1-d)*length to `to`, d*length to `from`; probed 2026-10-25), within `PLANET_KM` it sets `storage.approaching[player]` = destination and reconciles: the ships parked there (`draw.ships_at`) are added from ahead with `anim.approach`, and each tick n = 180*km/`PLANET_KM` (the planet's offset), once arrived the last bit steps at `ARRIVE_STEP`; turning away = they leave (retrace)  ( `storage.min_step` test override via `set_min_step` remote); mover = the viewer's platform when it moved, else the ship's own; ships always travel FORWARD = up the screen (the API gives no 2D heading): anchor y = `ship.base.y + geom.travel_dy(n/180, side, 150 * p)` = side*150*p*f^2 with f = n/180 (`DRIFT` 150: off screen at normal zoom; parallax p = 1 + `PARALLAX` 2 * (k - 1) = 0.7..1.3 from the ship's size factor k: nearer ships pass faster, owner: "not nice that both ships are perfectly aligned"), side -1 (`AHEAD`, above the spot) / +1 (`BEHIND`, below it); relative to the viewer: ANOTHER platform moving = leave AHEAD (flies on), arrive BEHIND (rises into its spot); the VIEWER's platform moving = leave BEHIND (falls behind, like the planet), arrive AHEAD (comes down into its spot); `storage.where[player]` = {platform, loc} last seen (set in reconcile and show) tells which moved, x never changes, scale 1->0.53 linear in f, NO fade on the way (alpha = min(1, (1-f)/`FADE_TAIL` 0.1): only the last tenth fades, a safety net when zoomed far out), a flip (reversal) keeps its side and retraces its path, `ship.base` = the spot (the anchor position when parked); staged drawing: `storage.draw_queue`, `FV_DRAW_BUDGET` = 150 objects/tick, one model gather/tick; ships under way: anchors move every tick, sprite updates (scale/offset/alpha) share `FV_FRAME_BUDGET` = 6000/tick across all viewers, least recently updated first (`ship.drawn_tick`), at least one ship per tick, only changed values written (`ship.drawn_k`/`drawn_fade`), scratch tables reused, the parked frame at an arrival end always exact (0.4.2, portal report: lag with many big ships)), `data.lua` (`fv-anchor`, sprites `fv-t1-0..15`/`fv-t2-0..15` floor pieces at true texture scale (`snapshot.floor_pieces`: 2x2 + 1x1 edge pieces; 0.5.0 FLOOR BLOCKS: `snapshot.floor_pieces(rects, max)` fills each rect with 8x8 then 4x4 blocks (`FLOOR_BLOCK` 8 in draw.lua), 2x2 / 1x1 only in the leftover strips; a block = ONE sprite `fv-t<4|8>-<v>` (data.lua) whose layers are the same 2x2 pictures at the same places with the same variants (`geom.floor_sub_variant`; unit test expands blocks and compares with max = 2), each layer `floor_scale(2)` larger, block drawn at S; one tint per block instead of per 2x2 (GUI stills 2026-11-16 vs 0.4.11: only faint speckle on bare floor, no seams). Why: moving an anchor costs ~14 ns per ATTACHED RENDER OBJECT whoever moves it (teleport, or the engine driving a car/character: `tests/bench/micro.sh`), hardly per layer (625 x 16-layer = 0.19 ms vs 10000 x 1-layer = 1.12 ms), and floor was 55% of a ship's objects (`HIST=1 tests/bench/bench.sh`). Stress bench 0.4.11 -> 0.5.0 (2 runs each, same session): objects 107213 -> 54500, smooth parked 2.35-3.18 -> 0.90-0.92 ms, balanced 0.39-0.43 -> 0.26-0.27, arrive mean 6.9 -> 4.2 (ticks > 16.7 ms 50-56 -> 13-14), leave 11.8-14.0 -> 7.3-9.7 (55-193 -> 3-7); first-arrival spike ~450 ms unchanged. Also 0.5.0: a float step on the same 1/256-tile grain is skipped (`geom.same_grain`; the engine stores positions in 1/256 tile and DOES draw scaled sprites at every grain: shot mode `subpx`, so any step above smooth is visibly coarser; zoom/resolution-based culling is NOT multiplayer safe); drawn `geom.floor_scale(size)` = 1 + `geom.FLOOR_OVERLAP` 0.1 / size larger so neighbours overlap: without it the renderer's per-sprite pixel rounding opened 1 px dark gaps between pieces at some sub-pixel positions, moving with the idle float = 'flashing lines', 0.4.5; `tools/shot-linux.sh <save> <out> seams` (`FV_IDLE_FRAMES`, `FV_IDLE_ZOOM`) = per-tick frames of a plain floor patch; `idle` also takes `FV_IDLE_SHIP`), `fv-px`, `fv-dot` running light; max 8 lights per ship), `graphics/px.png`, `graphics/dot.png`; `prototypes/pictures.lua` `find_layers(proto, dir)` (dir north/east/south/west, default north) picks the `<dir>` child of variant tables and `<dir>_graphics_set` (fusion generator), prefers `platform_graphics_set` (cargo bay) over `graphics_set`; `data-final-fixes.lua` writes `fv-e-<name>` (north) plus `fv-e-<name>-<dir>` ONLY when that direction's layers differ (`same_layers`: filename/x/y); model `ent.dir` (4 east, 8 south, 12 west, nil = north, also old stored models) is kept only for entities NOT turned by `rot` (belts/undergrounds/splitters/pipes/walls; pipe-to-ground is NOT turned since 0.4.8: its own picture per direction, `fv-e-pipe-to-ground-<dir>`, portal report Maxorio), `draw.sprite_for(name, dir)` tries directional, base, icon; `prototypes/pictures.lua` reads `size` before `width`/`height` like the game (Carna sets both, a stale width crashed sprite loading in 0.4.0; headless never loads sprites, so only a GUI load shows that class of crash); `data-final-fixes.lua` also writes mod-data `fv-lights` (light dir/colour per location, read at runtime)

No periodic blind rebuild.
